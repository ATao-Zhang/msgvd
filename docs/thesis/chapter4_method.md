# 第4章 基于语义增强执行路径证据的漏洞行级定位与可解释方法

本章围绕漏洞检测模型的可解释性不足问题，提出一种基于语义增强执行路径证据的漏洞行级定位与可解释方法。该方法以已有 MSAVD/DeepWuKong 漏洞检测模型为基础，不改变原始模型训练流程和检测任务目标，在模型完成样本级漏洞预测之后，进一步从执行路径节点证据、代码语义风险和轻量反事实扰动三个角度构建漏洞行级定位依据。方法输入为程序样本对应的 XFG（eXtended Flow Graph）图结构，输出包括样本漏洞预测概率、候选漏洞代码行排序结果以及 Top-k 漏洞行解释结果。

与仅给出二分类标签的漏洞检测方法相比，本文方法更关注模型判定结果背后的证据来源。通过将节点级证据映射到源代码行，并引入危险 API、内存操作、输入函数、数组与指针访问等语义风险规则，本文方法能够在保持原有检测模型不变的前提下，给出更符合安全分析人员认知习惯的漏洞行级解释结果。

## 4.1 问题定义

给定一个程序函数或代码片段样本，其对应的 XFG 记为 \(G=(V,E)\)，其中 \(V\) 表示图中的程序语句节点，\(E\) 表示节点之间的数据依赖、控制依赖或执行路径相关边。每个节点 \(v\in V\) 对应源代码中的一条或多条语句，并带有代码 token 序列、语句类型、源代码行号等信息。已有漏洞检测模型以 XFG 为输入，输出样本属于漏洞类别的概率：

\[
P_{vul}=f(G)
\]

其中，\(f(\cdot)\) 表示训练完成的 MSAVD/DeepWuKong 漏洞检测模型，\(P_{vul}\in[0,1]\) 表示样本存在漏洞的预测概率。传统漏洞检测任务通常只关心样本级标签，即判断代码是否存在漏洞。然而，在实际漏洞审计和修复场景中，仅知道函数存在漏洞是不充分的，安全分析人员更需要知道模型认为哪些代码行最可能与漏洞相关。

因此，本文将漏洞行级定位任务定义为：在给定 XFG 样本 \(G\) 及其模型预测概率 \(P_{vul}\) 的条件下，为每一条源代码行 \(l\) 计算定位分数 \(S(l)\)，并按照分数从高到低输出候选漏洞行序列：

\[
R(G)=\{l_1,l_2,\ldots,l_n\}, \quad S(l_1)\geq S(l_2)\geq \cdots \geq S(l_n)
\]

最终输出 Top-1、Top-3、Top-5 等候选漏洞行结果，用于衡量模型解释是否能够命中真实漏洞行。该任务的核心难点包括三个方面：第一，检测模型的预测结果是图级输出，需要将图级判断转换为行级证据；第二，神经网络注意力或节点分数可能关注到与漏洞相关但并非直接危险操作的上下文语句；第三，代码漏洞具有明显的安全语义特征，若完全依赖模型内部分数，可能无法充分利用危险函数和内存访问等先验知识。

基于上述问题，本文提出“基于语义增强执行路径证据的漏洞行级定位与可解释方法”，通过注意力证据分数、语义风险分数和反事实扰动验证共同构建漏洞定位解释。

## 4.2 方法总体框架

本文方法的总体流程如图 4-1 所示。首先，输入样本被表示为 XFG 图结构，图中节点保存代码 token、源代码行号以及执行路径相关信息。随后，将 XFG 输入已经训练完成的漏洞检测模型，获得样本级漏洞预测概率。与此同时，从模型中提取节点级证据分数，或在模型未显式提供注意力权重时构造可运行的节点重要性分数。然后，将节点证据依据源代码行号聚合为行级 Attention Score。

在此基础上，本文进一步根据源代码文本计算 Semantic Risk Score。语义风险分数不依赖训练过程，而是依据漏洞检测领域常见的危险代码模式进行规则化建模，包括危险字符串和内存拷贝 API、内存分配与释放函数、外部输入函数、数组访问、指针访问、长度边界检查以及算术操作等。该分数用于补充模型内部注意力证据中可能缺失的安全语义先验。

最后，本文将归一化后的注意力证据分数与语义风险分数进行线性融合，得到最终主排序分数，并输出 Top-k 候选漏洞行。对于排名靠前的候选行，本文还设计了轻量反事实扰动验证模块，通过对候选行对应节点的 token 序列进行长度保持型 mask，观察漏洞预测概率下降程度，从而判断该行对模型预测是否具有实际影响。需要说明的是，反事实分数主要作为可信度验证模块，用于辅助分析候选行解释的可靠性，而不作为本文最终主排序模块。

整体流程可以概括为以下步骤：

（1）读取测试集中的 XFG 样本，并加载训练完成的漏洞检测模型；

（2）输入 XFG，获得样本漏洞预测概率 \(P_{vul}\)；

（3）提取或构造节点级注意力证据分数，并映射到源代码行；

（4）基于代码行文本计算语义风险分数；

（5）融合注意力证据与语义风险，得到最终定位分数；

（6）输出 Top-k 漏洞候选行及其代码文本、分数和解释标签；

（7）对 Top-k 候选行进行轻量反事实扰动，验证候选行对模型预测概率的影响。

该框架具有两个特点：一是保持原始漏洞检测模型和训练流程不变，仅在推理与解释阶段增加后处理模块；二是将神经模型内部证据与人工安全语义规则结合，使定位结果同时具有数据驱动依据和安全分析可读性。

## 4.3 执行路径证据分数提取

执行路径证据分数用于刻画 XFG 中不同节点对模型漏洞预测结果的重要程度。由于 XFG 本身包含程序执行路径、数据依赖和控制依赖信息，节点分数可以被视为模型对执行路径中关键语句的关注程度。对于一个输入图 \(G\)，模型在完成前向传播后输出漏洞概率 \(P_{vul}\)。若模型内部提供节点注意力权重、节点门控分数或其他节点级证据变量，则优先直接使用该分数作为节点级 Attention Score。

设节点 \(v\) 的模型证据分数为 \(A(v)\)，其值越大，表示模型在判断样本为漏洞时越关注该节点。若模型提供路径级权重或路径级预测贡献，则可将路径级分数与节点级分数结合，形成最终节点证据：

\[
A'(v)=P_{path}\cdot A(v)
\]

其中，\(P_{path}\) 表示路径级重要性分数或模型输出的漏洞概率近似值。在当前实现中，若模型显式提供 path score，则使用该分数；若无明确路径分数，则使用样本漏洞预测概率作为最小可运行版本中的路径级替代分数。

由于最终定位对象是源代码行，而不是图节点，因此需要将节点级分数映射到行级分数。对于源代码行 \(l\)，令 \(V_l\) 表示映射到该行的节点集合，则行级注意力证据分数定义为：

\[
AttentionScore(l)=\max_{v\in V_l} A'(v)
\]

本文采用最大池化而非平均池化，是因为一行代码只要包含一个高度可疑的执行路径节点，就可能构成关键漏洞语句。最大池化能够保留最强证据，避免因同一行中其他低分节点稀释关键节点贡献。

在模型未能提供显式注意力或节点权重的情况下，本文采用节点表示向量的 L2 范数作为临时节点重要性分数。该替代方案可以保证解释流程可运行，但其解释性弱于模型显式注意力。因此，在实验与论文表述中，本文将其限定为最小可运行版本的 fallback 策略。

## 4.4 语义风险分数计算

仅依赖模型内部注意力证据可能存在两个问题：一方面，模型可能关注漏洞触发前的上下文语句，例如变量声明、分支条件或数据来源；另一方面，模型注意力不一定能够直接反映安全专家对危险代码模式的判断。为此，本文引入 Semantic Risk Score，用于刻画代码行文本中显式存在的安全风险语义。

语义风险分数采用规则化计算方式。对于每一条代码行，本文根据其文本内容检测是否包含危险 API、内存管理函数、输入源、数组或指针访问、长度边界相关函数以及算术操作等风险模式。不同风险模式赋予不同权重，具体如下：

（1）危险拷贝或字符串 API，权重为 1.0。该类操作包括 `strcpy`、`wcscpy`、`strcat`、`wcscat`、`sprintf`、`vsprintf`、`gets`、`memcpy`、`memmove`、`strncpy`、`wcsncpy` 等。这类函数常与缓冲区溢出、越界写入和字符串截断错误相关，因此赋予最高风险权重。

（2）内存分配、释放及相关 API，权重为 0.7。该类操作包括 `malloc`、`calloc`、`realloc`、`free`、`alloca`、`new`、`delete` 等。内存管理错误可能导致释放后使用、重复释放、内存泄漏和堆溢出等问题。

（3）输入源或外部输入函数，权重为 0.6。该类操作包括 `scanf`、`fscanf`、`sscanf`、`fgets`、`fread`、`read`、`recv`、`getenv`、`argv`、`atoi`、`atol`、`strtol` 等。外部输入是漏洞触发的重要来源，对其进行标记有助于识别数据流起点。

（4）数组访问或指针访问，权重为 0.5。数组下标、指针解引用和结构体指针访问常与越界访问、空指针引用和非法内存访问有关，因此作为中等风险语义特征。

（5）长度或边界相关函数，权重为 0.4。该类操作包括 `strlen`、`wcslen`、`sizeof` 等。长度计算既可能是安全检查，也可能参与错误的缓冲区大小计算，因此给予中等风险权重。

（6）整数和算术操作，权重为 0.2。该类操作包括 `+`、`-`、`*`、`/`、`%`、`<<`、`>>` 等。算术运算可能涉及整数溢出、长度计算错误和位移错误，但单独出现时风险相对较弱，因此赋予较低权重。

对代码行 \(l\)，语义风险分数定义为各命中规则权重之和，并裁剪到 \([0,1]\) 区间：

\[
SemanticScore(l)=clip\left(\sum_i w_i\cdot I_i(l),0,1\right)
\]

其中，\(I_i(l)\) 表示代码行 \(l\) 是否命中第 \(i\) 类风险规则，\(w_i\) 表示该类规则权重。采用 clip 操作的原因是避免同一代码行因同时命中多个规则而获得过高分数，从而破坏与注意力证据分数之间的量纲平衡。

## 4.5 注意力证据与语义风险融合

为了综合模型内部证据和外部安全语义知识，本文对 Attention Score 与 Semantic Score 进行归一化后融合。归一化的目的是消除不同分数来源的量纲差异，使二者能够在同一尺度上进行线性组合。

对于一个样本中的所有候选代码行，分别对注意力证据分数和语义风险分数进行 min-max 归一化：

\[
AttentionScore_{norm}(l)=\frac{AttentionScore(l)-A_{min}}{A_{max}-A_{min}}
\]

\[
SemanticScore_{norm}(l)=\frac{SemanticScore(l)-S_{min}}{S_{max}-S_{min}}
\]

其中，\(A_{max}\)、\(A_{min}\) 分别表示当前样本中行级注意力证据分数的最大值和最小值，\(S_{max}\)、\(S_{min}\) 分别表示当前样本中语义风险分数的最大值和最小值。当最大值与最小值相等时，采用稳定的默认归一化处理，避免除零错误。

最终定位分数定义为：

\[
FinalScore(l)=(1-\lambda)AttentionScore_{norm}(l)+\lambda SemanticScore_{norm}(l)
\]

其中，\(\lambda\) 为语义风险权重，用于控制语义规则对最终排序的影响。当 \(\lambda=0\) 时，方法退化为纯注意力证据排序；当 \(\lambda=1\) 时，方法退化为纯语义规则排序。通过实验扫描，本文最终选取 \(\lambda=0.9\)，即更强调语义风险分数，同时保留少量模型注意力证据。这一设置体现了漏洞行级定位任务的特点：真实漏洞行往往具有明确的危险操作语义，而模型注意力则能够补充上下文执行路径信息。

融合后的分数用于生成最终主排序结果。对于每个样本，按照 \(FinalScore(l)\) 从高到低排列代码行，并输出 Top-1、Top-3、Top-5 候选漏洞行。

## 4.6 反事实扰动可信度验证

为了进一步验证候选漏洞行是否真正影响模型的漏洞预测结果，本文设计了轻量反事实扰动模块。该模块不参与模型训练，也不改变数据预处理流程，而是在推理阶段对 Top-k 候选行进行局部扰动，并观察模型输出概率变化。

对于候选代码行 \(l\)，设原始样本漏洞预测概率为 \(P_{original}\)。对该行对应的 XFG 节点进行 mask 后，重新输入模型，得到扰动后的漏洞预测概率 \(P_{masked}\)。反事实分数定义为：

\[
cf\_score(l)=\max(0,P_{original}-P_{masked})
\]

若 mask 某行后漏洞概率明显下降，说明该行对模型判断样本为漏洞具有较强贡献；若概率变化较小，则说明该行虽然在主排序中靠前，但对模型预测的实际影响有限。

考虑到完整逐行扰动计算成本较高，本文仅对当前排序前 Top-k 候选行执行反事实扰动。mask 方式采用 token-level length-preserving mask，即对候选行对应节点的 token 序列进行长度保持型替换：原本为 PAD 的位置保持 PAD，原本非 PAD 的 token 替换为 UNK、MASK 或合法的非 PAD 替代 token。该设计避免将节点 token 序列全部置为 PAD，从而导致 RNN 编码器接收到长度为 0 的输入。同时，候选节点的附加语句特征可以置零，以增强扰动效果。

需要强调的是，本文将反事实模块定位为可信度验证模块，而不是最终主排序模块。原因在于，反事实扰动受到模型结构、token 替换策略和候选行数量限制的影响，其分数更适合用于解释可信度分析，而不宜直接替代注意力与语义风险融合后的主定位分数。

## 4.7 漏洞行级定位输出

本文方法最终输出面向漏洞审计场景的行级解释结果。对于每个测试样本，输出内容包括样本编号、真实样本标签、模型漏洞预测概率、模型预测标签、真实漏洞行集合、行级标签来源、候选漏洞行排序以及 Top-k 代码行解释信息。

对于每条候选代码行，输出字段包括源代码行号、代码文本、注意力证据分数、语义风险分数、最终融合分数、语义风险标签，以及在执行反事实验证时得到的概率下降值。该输出形式能够同时满足定量评价和人工分析需求。定量评价时，可以直接使用排序后的行号序列计算 Top-k Accuracy、MRR 和 IFA 等指标；人工分析时，研究者可以结合代码文本和语义标签理解模型为何将该行判定为高风险。

具体而言，Top-k 输出可以表示为：

\[
TopK(G)=\{(l_i,S(l_i),code(l_i),tags(l_i))\}_{i=1}^{k}
\]

其中，\(l_i\) 表示第 \(i\) 个候选行号，\(S(l_i)\) 表示最终定位分数，\(code(l_i)\) 表示该行源代码文本，\(tags(l_i)\) 表示该行命中的语义风险标签。通过该形式，本文方法不仅给出“哪一行可疑”，还给出“为什么该行可疑”的解释依据。

## 4.8 本章小结

本章提出了基于语义增强执行路径证据的漏洞行级定位与可解释方法。该方法在不改变原始 MSAVD/DeepWuKong 模型训练流程的前提下，从模型节点证据、代码语义风险和反事实扰动验证三个角度构建漏洞定位解释。首先，方法从 XFG 和模型前向传播过程中提取节点级执行路径证据，并映射为行级 Attention Score；其次，依据危险 API、内存操作、输入源、数组指针访问、边界函数和算术操作等规则计算 Semantic Risk Score；随后，将二者归一化后进行线性融合，并通过实验确定最终语义权重 \(\lambda=0.9\)；最后，对 Top-k 候选行进行轻量反事实扰动，以验证候选行对模型漏洞预测概率的影响。

该方法兼顾了神经模型内部证据和安全领域先验知识，能够输出可用于定量评价和人工审计的漏洞行级定位结果。下一章将围绕 SARD 数据集，设计实验验证本文方法在 Top-k 命中率、MRR 和 IFA 等指标上的有效性。
